# 进度

给下一次接手的人（或者下一段对话里的我）看的：现在做到哪、怎么验证、接下来做什么。规矩、流程、代码地图和用语表在仓库根目录的 `CLAUDE.md`。

## 现状（v1.2.0-alpha.1）

- **两个模式**，标题界面选：一路 3v3（数值冻结）、三路 5v5（王者式地图、战争迷雾）。
- **十八位修士**，两个模式共用招式机制。共用数值在 `src/config.js` 的 `HEROES`；各模式的修正在 `MODES.<模式>.heroTune`（乘在基础气血、攻击、术法上）和 `MODES.<模式>.tune`（兵线、塔、野怪、时间点）。
- **三路的地图**：野区和线之间有实体山脊（一排巨石，留有入口），宗门的石栏和山门柱也是实体。寻路用 Yuka 的图搜索。一路没有墙，仍是直线加避障。
- **三路的电脑**：
  - 按位置组队（`SEATS`、`SEAT_FIT`）。
  - 空闲时做什么由 Yuka 的 `Think` 仲裁，位置权重在 `SEAT_BIAS`：巡山清野、抓人、支援；护法跟着养剑位、不抢补刀；中军在自己线稳的时候会游走。
  - 撤退、回应信号、全队集结（11 分钟后）、被压内塔回防仍是优先级判断。
  - 会在队内说话，包括"某路的某某不见了"。
- **信号**：集合 / 进攻 / 撤退（`Z` `X` `C` 或小地图下的按钮），外加一个**开团开关**（`V`）：开着时同门一直跟着玩家、打玩家打的目标，照样不送死；玩家陨落自动解除。
- **三路的目标**（三者各有自己的模型）：上河道血海残魂（全队伤害），下河道镇渊傀（己方弟子强化 55 秒），15 分钟后上河道换成渊主残念（弟子大幅强化 90 秒加全队伤害）。
- **一路的电脑**还是原来的 if 链，没有动。

## 怎么验证

```bash
npm run dev                                      # 先起服务
node batch.mjs 36 0 1500 mirror single           # 一路回归：平均约 15–16 分钟，一边倒 10%–15%
node batch.mjs 16 0 2700 mirror tri              # 三路：平均约 18–21 分钟
node analyze.mjs runs/<文件>                      # 汇总
# 位置演算见 docs/打位演算.md
```

改了共用机制或地图代码，两个模式都要跑；一路的树石布局和数值不应变化。

## 踩过的坑

- macOS 文件系统不分大小写，`runs/A0.jsonl` 会覆盖 `runs/a0.jsonl`。
- `rm` 带通配符会被拦，测试产物靠 `.gitignore` 挡在仓库外，不必清。
- 地面着色器是按当前模式生成的字符串；凡是写死的地图尺寸（80、48、64、75）都要换成 `MAP` / `POS`。上一次漏了"界外压暗"，把三路的山门涂黑了。
- 一路的车道是公式（s 就是 x），三路的是折线路径。改电脑逻辑时用 `L.at / L.proj / sOf`，不要直接用世界坐标的 x。
- 无头浏览器里 `requestAnimationFrame` 被限速，截图前用 `__moba.sim(秒)` 推进，动画类效果（慢动作、镜头推近）测不到。
