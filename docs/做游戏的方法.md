# 做游戏的方法（从《霜烬之争》总结）

给下一款游戏用的 context 文件。新游戏开工时，把这份放进新仓库（或在新对话里先读它），照着做就能少走霜烬之争走过的弯路。具体代码都在霜烬之争的仓库（`desmond-zhou/mini-moba-frost-and-ember`）里，下面写到的文件可以直接拷过去改。

---

## 0. 作者的规矩（所有游戏通用）

- 用中文回复。作者很忙：**自己测、自己查、自己拿主意**，拿了主意要说清替他定了什么；只有真拿不准、又会改变做法的才问。
- **做完一块就发布一版**：测试 → 打包 → 发布到网页 → 提交推送打标签。作者在手机和电脑上随手试玩，反馈来得很快。
- **能写成代码的测试都写成代码**，发现一个问题就补一条测试，测试套件只增不减（见第 7 节）。
- **能用库就用库**，只自己写库没覆盖的部分。
- 标题界面要有作者署名：「制作 · Desmond Zhou 周易　微信 desmondzhou　© 2026 版权所有」，名字和版权链接到 https://desmondzhou.com 。
- 公开发布的东西不放作者的私人信息（真实邮箱等）；提交用 GitHub 免打扰邮箱。
- 名字和用语要贴合游戏的世界观（霜烬之争是修仙：修士、灵石、归宗……），不能出戏；界面不要啰嗦，不做过度教学。
- 不要把每个决定同步到记忆、日历或别的助理，除非作者要求。
- 部署到作者的东西（AWS、域名、服务器）前先说清楚花多少钱；对公网开放、删除这类不可逆的操作要先问。

## 1. 形态：一个 HTML 文件，零素材文件

- **整个游戏打包成一个自带一切的 HTML**（`build.mjs` 用 esbuild 把 `src/` 和库打成一个 iife，塞进 `index.html`）。双击就能玩，能发成 claude.ai 的 artifact，能放 S3，能装成 Mac 应用。
- **没有任何图片、模型、音频文件**：贴图、人物、图标、头像、音乐、音效全是代码在加载时生成的（第 2 节）。好处：体积小（压缩后约 400 KB），不用管素材授权，改风格只改代码。
- 开发时不打包：`serve.mjs` 起一个静态服务器，`index.html` 用 importmap 直接加载 `src/*.js` 和 `node_modules` 里的库，改完刷新即可。少数库（Tone.js）要先用 `vendor.mjs` 预打成单文件。
- 版本号三处一起改：`index.html` 的 `.ver`、`package.json`、`README.md`。

## 2. 素材怎么生成

| 要什么 | 怎么做 | 霜烬之争里的文件 |
|---|---|---|
| 地面、地形 | 一个按地图生成的 GLSL 着色器：噪声、生物群落混合（霜→草→焰）、车道、河、地界。地图尺寸一律从配置读，不写死 | `world.js`、`mat.js` |
| 树、石、草 | 基本几何体变形 + 实例化（InstancedMesh）；树叶是在 canvas 上画好的贴图卡片 | `world.js` |
| 人物 | 每个角色一张「服装表」（体型、颜色、武器、配饰），由基本几何体拼装 + 简单骨架动画 | `heroes.js`、`models.js` |
| 头像、技能图标 | 在 canvas 上按参数画（类似矢量图），按队伍色染色，生成 data URL | `portraits.js`、`icons.js` |
| 特效 | 粒子池、贴花、光柱、拖尾，全部复用对象池；血条用一个 instanced 的着色器一次画完 | `fx.js`、`vfx.js` |
| 音效 | **Tone.js 离线渲染**：每个音效是一段合成「配方」（敲击、噪声、颗粒、FM、拨弦），开局时在后台渲染成 AudioBuffer，播放就是播 buffer。按角色和招式的性质设计（刀是金属、法术是 FM 和颗粒），普通攻击短促，大招突出 | `sfx.js`、`skillsound.js` |
| 音乐、环境音 | 同样离线渲染：几种乐器、按局势换情绪；环境音是几段 8 秒循环（雪、林、河、血池），按镜头位置交叉混合 | `sfx.js`、`audio.js` |
| 混音 | 一张音量表、空间定位、大场面时压低其他声音（ducking）。手机上 iOS 要设 `audioSession` | `audio.js` |
| 文字、人设 | 角色、台词、简介取材自作者的小说设定；台词按性格写，敌我说话不同 | `config.js`、`barks.js` |

经验：
- 先做一个能看的版本，再按作者反馈一点点加质感：光影、顿帧、慢动作、镜头推近、受击闪白、环境音。
- 着色器和材质缓存的键要带上「模式 / 地图」，换地图时重建世界。
- 阴影跟着镜头走时，要在光源空间按像素网格对齐，否则走路时阴影会闪。

## 4. 电脑 AI 怎么做

- **数据驱动的招式**：每招是一个 `kind`（proj / zone / dash / strike / nova / haste …）加参数；区分度靠参数，不靠新代码。电脑怎么用每种 `kind`，写在一个 switch 里。
- **分层决策**（`botThink`）：
  1. 必须做的事（撤退、回应信号、集结或回防、围剿目标、回去买东西）按优先级判断；
  2. 空闲时做什么交给 Yuka 的 `Think` 仲裁：每个选项是一个 GoalEvaluator，按局势打 0–1 分，再乘以「位置」的偏好权重（镇关、中军、养剑、护法、巡山）。
- **打团按定位**：前排先上，后排挑残血、被贴脸就边打边退、不越过前排，刺客等别人先手。
- **队伍层面的计划**（`teamThink`）：集结推哪路、被压时回防，并在队伍聊天里喊出来。
- **出装**：第一件按演算出的核心装备，之后按「这件东西对我的收益 × 位置权重 × 局势（落后偏防、领先偏攻、对面物理多就买护甲）」现场打分。
- **难度**只改反应时间、瞄准误差、伤害系数；联机时两边电脑用同一套数值。
- **说话**：按事件（击杀、阵亡、领先、落后、开团、点名针对）和角色性格出台词；敌人只说闲话不报情报；有冷却，不刷屏。
- 写电脑逻辑时用「沿车道的距离 s」而不是世界坐标，换地图才不会坏。

## 5. 快速模拟和平衡

- **游戏必须能无头、快速地跑**：`__moba.sim(秒)` 不画画面只推进逻辑，一局 20 分钟的 5v5 几秒钟就跑完（约实时的 280 倍）。这是一切平衡工作的基础，新游戏从第一天就要留好这个入口。
- **镜像对打**（`batch.mjs`）：两边全是电脑、用同一套数值，开 6–8 个进程并行打几百局，每局输出一行 JSON（胜负、时长、每人的击杀/阵亡/伤害/出装）。
- **汇总**（`analyze.mjs`）：每个角色的胜率、KDA、伤害，平均时长，一边倒的比例。
- **样本量**：每个角色少于 250 局的胜率不要信（同一套数值、每人约 70 局的四批，同一个角色分别是 29%、29%、50%、40%）。
- **调参**（`tune.mjs`）：按胜率自动算修正倍率，噪声范围内不动；只动「每个模式一张的单人修正表」，不动共用的招式机制；用 `gapcheck.mjs` 守住作者定的规矩（倍率 0.90–1.15，两个模式相差不超过 0.08）。
- **专项演算**：出装演算（`builds.mjs`，每人每种第一件装备各跑一批）、位置演算（`seats.mjs`）、节奏（`pace.mjs`，每分钟的平均等级）、单招机制定点检查（`mech.mjs`）、性能剖析（`prof.mjs`、`frameprof.mjs`）。
- 任何「感觉某某太强 / 太弱」先跑数据再动手；改共用代码后，两个模式都要跑回归。

## 6. Playtest（试玩）的方法

- **作者是第一个玩家**：每做完一块就发一版能玩的，让他在手机和电脑上随手试，反馈常常是一句话（「射手技能太像」「死了的读秒没有」）。每条反馈当场修、当场发。
- **三种屏幕都要看**：手机竖屏、手机横屏、电脑，外加不常见的尺寸。界面问题用自动截图加断言来防（`tests/layout.mjs`）。
- **截图自查**：每改一处界面，就在三种尺寸下截图自己看一遍，再发给作者。
- **记录决定**：作者拍板的规则（平衡口径、人设、哪些不做）写进仓库的 `CLAUDE.md` 或 `docs/进度.md`，下次接手的人照做。
- **真人试玩之前先用「假人」**：自动化的玩家像人一样乱点（`nettest.mjs` 的 `HUMAN=1`），先把会坏的地方找出来。
- **测试不要碰线上**：线上的大厅里出现测试玩家很难看；测试一律用本机服务器。
- 有些问题只有真人试玩才发现（手机静音键、iOS 后台、聊天没有发送键、按钮被误套样式），发现一个就补一条自动测试。

## 7. 测试（写成代码，越积越多）

```bash
npm run test:quick     # 约 6 分钟，发布前必跑
npm run test:all       # 约 25 分钟，改了决定胜负的代码时跑
```

| 测什么 | 文件 |
|---|---|
| 不开浏览器的单元测试：确定性数学、配置自洽、联机时钟、服务器的防刷限制 | `tests/unit.test.mjs`（node --test） |
| 平衡表守规矩 | `gapcheck.mjs` |
| 单机冒烟：开一局、推进 90 秒、不报错 | `test.mjs` |
| 确定性：两台视角、画质、镜头都不同的机器跑同一局，每 30 秒的指纹逐位相同；`CMDS=1` 时再加上同一串随机真人指令 | `dettest.mjs` |
| 服务器规则（直接走协议）：大厅、房间号、重名、版本不同被拒、准备倒数、立即开战、指令校验、不同步上报、断线托管与重连、刷屏断开、最后一人离开关房 | `servertest.mjs` |
| 大厅和房间，两个浏览器像人一样用 | `tests/lobbytest.mjs` |
| 同门的聊天、信号、开团 | `chattest.mjs` |
| 联机对局：真人乱点、断线重连；打完整局回到房间 | `nettest.mjs`（`HUMAN=1`、`TOEND=1`） |
| 各种屏幕下按钮都在屏幕内、没有横向滚动 | `tests/layout.mjs` |

总入口 `tests/run.mjs` 会自己起本机的页面和服务器，逐项跑，出汇总，每项的完整输出存在 `runs/suite_*.log`。

## 8. 网络对战怎么做

**做法：帧同步（lockstep）**。每台机器都跑整局，服务器只转发操作。选它的理由：画面、声音、界面一行不用改，单机和联机走同一套代码；服务器只是个约 200 行的转发器，几乎不占资源。代价：

- 必须保证每台机器算得逐位相同；
- 迷雾挡不住改客户端的人。朋友之间玩可以接受，公开运营要换成服务器权威。

**要让每台机器算得一样，必须守的规矩**：
1. 逻辑按固定步长走（每步 1/60 秒，`G.step`），画面每帧单独画（`G.draw`，在两步之间插值）。
2. 决定胜负的模块用 `dmath.js` 代替 `Math`：sin、cos、atan2、hypot 用加减乘除重写（各浏览器的原生版本末位可能不同）；`Math.random` 换成每局一个种子的随机数；不用 `**`。
3. 只为好看的随机（火花、台词挑哪句）用 `vis()`，不能动到对局的随机数。
4. 逻辑里绝不读「这台机器才有的东西」：本机玩家是谁、镜头在哪、画质、网址参数。这些只用来决定「这台机器看见、听见什么」（`me(h)`、`near()`）。
5. 玩家的一切操作都变成指令 `{c: …}`，单位用 id 传，由 `G.exec` 执行。单机当场执行，联机发给服务器、随回合回来再执行。
6. 构建时给决定胜负的代码算指纹（`__SIM__`），房间只收同一指纹的页面。

**服务器（`server/hub.mjs` 与运行环境无关，`server/server.mjs` 是 Node 版）**：
- 大厅：在线人数、房间列表、大厅聊天。
- 房间：座位、选人、准备、全员准备后倒数 10 秒自动开战、房主可以立即开战、空位由电脑补。
- 对局：每 50 毫秒发一个回合（这段时间所有人的指令），每回合 3 步；每 2 秒各机器报一次指纹，不一致就记录。
- 断线：座位交给电脑；重连时把整局指令记录发过去，几秒追上。
- 防滥用：每个地址的连接数、开房频率、试错房间号次数、每秒消息数都有上限；本机的测试连接不受限。
- 对局统计：每条事件写一行 JSON，只在 Tailscale 里能看。

**客户端（`src/net.js`）**：按回合到达的节奏推进，手里留约两回合防抖；落后就加速追，大幅落后时每帧最多追 3000 步。摇杆、按住右键这类连续指令每 40 毫秒只发最新的一次。切到后台超过 8 秒自动托管，回来自动交还。

研究过、暂时没用的：服务器权威 + 客户端预测（公开运营时才需要）、WebRTC 点对点、WebTransport、Colyseus、Nakama、Cloudflare Durable Objects（没人玩不花钱，但只能跑为它专门写的代码）。研究文档：https://claude.ai/artifact/AuhGvDd3REp4KSwtDo7nwh

**下一款游戏的放法**：页面另开一个子域名（`xxx.app.desmondzhou.com`），照 `deploy/publish.sh` 再建一个桶和 CloudFront。联机的话，同一台 Lightsail 上用 Caddy 再开一个端口或子域名，转给新游戏自己的 hub。成本：页面几乎为零；服务器已经在付的 5 美元可以多个游戏共用。

**中国大陆**：私下给朋友玩、不收费不需要版号；面向大陆公开收费发行绕不开版号。服务器在大陆以外不需要 ICP。详见 `docs/联机与发行笔记.md`。

## 10. 新游戏开工清单

1. 新仓库：拷 `build.mjs`、`serve.mjs`、`vendor.mjs`（需要 Tone.js 时）、`index.html` 的骨架（标题、HUD、菜单、全屏按钮、作者署名）、`CLAUDE.md` 的结构。
2. 先定**一屏能玩的核心循环**，配置全放 `config.js`（数据驱动），逻辑放 `game.js`。逻辑从第一天起就要：固定步长，用 `dmath.js` 代替 `Math`，玩家操作走指令，有 `__moba` 一样的调试与无头模拟入口。这样以后加联机和批量模拟都不用返工。
3. 素材全部程序生成，先粗后细；音效用 Tone.js 离线渲染。
4. 电脑 AI：必须做的事加 Yuka Think 仲裁，按定位加偏好。
5. 加 `batch.mjs` / `analyze.mjs`，平衡靠数据。
6. 测试：拷 `tests/run.mjs` 的结构，从单元测试、冒烟、截图和布局开始，每发现一个问题补一条。
7. 发布：先发 artifact 给作者试玩；稳定后建子域名的 S3 + CloudFront。
8. 要联机：拷 `dmath.js`、`net.js`、`server/hub.mjs`、`server/server.mjs`、`deploy/server.sh`，改指令表和阵容即可。

## 11. 踩过的坑

- 在一行代码中间插入 `//` 注释会吞掉后半行（两次导致页面启动失败）。用脚本改代码后必须 `node --check`。
- 用户界面的提示框放在对局 HUD 里，结果在标题和大厅界面里根本看不到。
- 新加的元素用了已有的类名（`.go`），被套上大按钮的样式。
- 帧同步的不同步来源：原生三角函数、`**`、只为好看的随机数和对局共用、读本机玩家或镜头的逻辑、地形噪声用 `sin` 做哈希（会影响障碍物位置）。
- 同一个身份开两个页面互相踢、无限重连：被顶掉的一方要停止重连。
- 服务器把缺失的身份号当成字符串 "undefined"（正则会把 undefined 转成字符串再匹配）。
- 测试脚本读服务器日志判断不同步，被别的测试故意制造的不同步误伤：只看自己这局的房间号。
- 同一个 IP 的开房频率限制，会挡住本机连续跑的测试：本机地址豁免。
