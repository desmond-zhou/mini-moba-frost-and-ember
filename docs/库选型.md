# 库选型

原则：能复用成熟开源的就复用，自己只补缺口。文件大小不是硬约束，流畅才是。

## 结论

| 需求 | 选择 | 理由 |
|---|---|---|
| AI 决策、记忆、调度、寻路图、邻近查询 | **Yuka 0.7.8**（MIT） | 和三路策划的架构逐条对得上，见下表 |
| 行为树 | 不用 | 行为树适合写死的流程；我们的仲裁是"哪个模式意愿最高" |
| 导航网格 | 不用 | 地图是程序生成的，没有现成网格；路点图够用 |
| 后处理 | 暂不换 | 现在不是瓶颈，见下 |
| 弟子合批渲染 | 自己写 | 弟子是刚体网格，用 three.js 自带的 InstancedMesh 就行 |
| 调参面板 | lil-gui | 很小，调 AI 权重和数值时现场拖动 |

## Yuka 和策划的对应

已核实：从 npm 取了 0.7.8，读了它的导出清单；协议 MIT；整包压缩后 123 KB；只取下表这些类打包后约 68 KB。

| 策划里的东西 | Yuka 里现成的 | 用法 |
|---|---|---|
| 模式 + 意愿 + 位置权重（2.3–2.5 节） | `Think`、`GoalEvaluator`、`CompositeGoal` | 每个模式一个评估器，`calculateDesirability` 返回意愿，`characterBias` 就是位置权重 |
| 敌人最后出现的位置（2.6 节） | `MemorySystem`、`MemoryRecord` | 迷雾下记"谁、在哪、多久前看见的" |
| 错开思考（3.3 节） | `Regulator` | 按频率节流，各人相位不同 |
| 路点图寻路（1.5 节） | `Graph`、`AStar` | 六七十个节点的图上搜一次 |
| 找附近单位（3.3 节） | `CellSpacePartitioning` | 网格分区，替换现在的两两比较 |

不用它的部分：`Vehicle`、转向行为、`EntityManager`。移动、碰撞、推挤我们已经有一套并且调过手感，两套移动系统混用是自找麻烦。

没核实的：它最后一次发版的日期和维护活跃度。所以锁定 0.7.8 这个版本，不跟更新。

## 后处理为什么先不换

- 常被推荐的组合是 pmndrs/postprocessing（把多个效果并进一个着色器）加 N8AO（环境光遮蔽）。
- 论坛上对它到底快多少说法不一，也没找到 N8AO 对 three.js 自带 GTAO 的实测对比。
- 我们现在实测：最高画质每帧 6.2 毫秒，低画质 1.15 毫秒（1440 × 810，这台 Mac mini）。后处理不是瓶颈。
- 我们的调色那一遍是自己写的（水墨描边、受击泛红、冲击模糊都在里面），换库要重写。

结论：三路第 6 期做手机适配时，如果手机上确实卡在后处理，再在我们自己的场景里实测后决定。

## 其他看过的

| 库 | 用途 | 结论 |
|---|---|---|
| mistreevous、behaviortree | 行为树 | 不需要 |
| PathFinding.js | 网格寻路 | 不需要，路点图更省 |
| three-pathfinding | 导航网格寻路 | 需要先有网格，不合适 |
| recast-navigation-js | 自动生成导航网格（WASM） | 能力最强，但 WASM 塞进单文件麻烦，规模也用不上 |
| InstancedMesh2 | 带骨骼的大批量实例 | 弟子没有骨骼，用不上；将来修士上百才考虑 |
| Tone.js | 音频合成框架 | 没有核实，只是印象。现在的音效是直接写 Web Audio；等你听过新音效说了感受再决定 |
